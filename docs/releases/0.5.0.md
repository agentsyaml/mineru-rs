# MinerU Rust 0.5.0

## Highlights

- The opt-in official HTTP API is rebuilt against the MinerU 4.2.3 task
  contract. Routes, request bodies, status codes, and the error envelope now
  match upstream, so existing MinerU 4.2.3 clients work unchanged.
- Each input file produces exactly one artifact. `default` returns a
  `result.zip` with `markdown.md`, `middle_json.json`, and
  `structured_content.json`; a lone `docx` or `html` request returns
  `document.docx` or `document.html` directly; `latex` returns a `result.zip`
  with `document.tex`. Images are included when the selection needs them.
- URL inputs are validated against the upstream rule: every resolved address
  must be public unicast, each redirect hop is re-checked, and the validated
  address is pinned for the connection. Loopback, private, link-local, and
  cloud metadata endpoints are rejected with `unsupported_source`.
- `office2pdf` 0.11.0 replaces 0.6.5. The local patch set drops from six
  crates to two (`citationberg`, `anydoc`), and the published `office`
  advisory count falls from 13 to 2.
- Rust 1.92 or newer is required.

## Breaking changes

- The official API route set is the 4.2.3 one: `POST /v1/tasks` (JSON only,
  202), `GET /v1/tasks/{task_id}`,
  `PUT /v1/tasks/{task_id}/uploads/{file_id}`, and
  `POST /v1/tasks/{task_id}/cancel`. `/v1/uploads*`, `GET
  /v1/tasks/{id}/result`, `POST /v1/file_parse`, `GET /v1/files`, and `DELETE
  /v1/files/{id}` are gone.
- `output_formats` accepts `default`, `docx`, `html`, and `latex`. The previous
  `markdown`, `middle_json`, `structured_content`, and `zip` values are
  invalid.
- `OfficialOutputFormat` and `OfficialParseResult::json()` follow the new
  vocabulary; `markdown()` reads `markdown.md` out of the `default` archive.
- Errors no longer carry a `type` field. Unknown tasks and files return 404
  `task_not_found` and `upload_not_found`.
- `rust-version` moves to 1.92 because `office2pdf` 0.7.0 and later require it.

## Compatibility

The pinned upstream references are MinerU 4.2.3, DocVortex 0.6.24, and
mineru-vl-utils 2.0.9, which upstream couples through
`docvortex<0.7,>=0.6.24` and `mineru-vl-utils<3,>=2.0.9`. The official worker
needs Python 3.11 through 3.14 and refuses to start when the installed `mineru`
reports a different version. Compatibility checks are model-free smoke checks,
not a claim of full Rust PDF/OCR parity.

## crates.io dependency advisories

The published crate resolves its Office dependencies from the registry because
workspace `[patch.crates-io]` entries do not reach consumers. Enabling `office`
reports 2 findings and `legacy-office` reports 8; default features and
`local-inference` are clean. Upgrading `office2pdf` to 0.11.0 cut the `office`
count from 13 to 2. The `legacy-office` count rose from 4 to 8 because
`anydoc` 0.2.4 still resolves `zip` 8.6.0 and four newer `zip` advisories were
published after the 0.4.1 audit. The `zip` findings are not reachable through
this crate, and the `quick-xml` findings are bounded by the Office helper's
resource limits. See
[compatibility](../compatibility.md#published-crate-dependency-advisories) for
the full list, the reachability audit, and the upstream conditions that clear
it.

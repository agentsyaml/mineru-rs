# MinerU Rust 0.4.1

## Highlights

- Published to crates.io. The 0.4.0 line was released to PyPI, npm, GHCR, and
  GitHub Releases only; this release restores the crate.
- Layout preprocessing now matches MinerU 4.0.12 exactly: fixed 800x800 cubic
  resize (kernel a = -0.75, half-pixel centers, edge clamp, uint8 fixed-point
  weights), RGB, and division by 255 with no mean/std subtraction. Output is
  byte-exact against docvortex 0.6.0 golden fixtures.
- ONNX input metadata is validated fail-closed before preprocessing: float32
  only, exact rank, static dimensions, no casting.
- Server `server_url` overrides now clear the API key and all configured custom
  headers. This is an intentional compatibility change.
- The strict ZIP scanner rejects the Info-ZIP Unicode Path extra field
  (`0x7075`) in central and local headers. Archives relying on it are no longer
  accepted.
- Combined task ZIP responses are bounded by the store ZIP cap and 100,000 total
  entries including the manifest, with preflight plus a bounded write cap.
- Optional Vulkan Compose profiles (`vulkan`, `vulkan-nvidia`) for AMD, Intel,
  and NVIDIA hosts; vLLM uses the static `openai-server` profile.

## Compatibility

The pinned upstream references are MinerU 4.0.12, DocVortex 0.6.0, and MinerU
Utils 2.0.7. Compatibility checks are model-free smoke checks, not a claim of
full Rust PDF/OCR parity. Older VLM inputs remain supported by default.

## crates.io dependency advisories

The published crate resolves its Office dependencies from the registry because
workspace `[patch.crates-io]` entries do not reach consumers. Enabling `office`
reports 13 findings and `legacy-office` reports 3; default features and
`local-inference` are clean. The nine `zip` findings are not reachable through
this crate, and the four `quick-xml` findings are bounded by the Office helper's
resource limits. See
[compatibility](../compatibility.md#published-crate-dependency-advisories) for
the full list, the reachability audit, and the upstream conditions that clear
it.
